# 为了少点一次「显示更多选项」，我写了一个软件

> 一个关于 Windows 11 右键菜单、7-Zip，还有 34 条菜单项的碎碎念。

## 一切的起点，是那一次多余的点击

我用 7-Zip 的频率大概是这样：下载一个压缩包，右键，解压。一天下来十几次，多的时候几十次。

在 Windows 10 上，这个动作是：右键 → 「7-Zip」→ 「解压到 xxx\」。

到了 Windows 11，它变成了：右键 → 「显示更多选项」→ 等半秒 → 「7-Zip」→ 「解压到 xxx\」。

多了一次点击，多了一次等待。听起来微不足道，对吧？问题是这件事一天要发生几十次，一年就是上万次。每一次那半秒的加载动画转出来，我心里都会默默地骂一句。

微软当年改这版右键菜单的想法我能理解：旧菜单确实太长了，装几个软件就能堆出二十几项，还有一堆「使用 XXX 打开」。所以他们做了一版只显示常用操作的紧凑菜单，把剩下的塞进「显示更多选项」里——顺便，这个名字起得也很诚实，它确实只是「更多选项」，不是什么「旧版菜单」。

但问题在于：**这个紧凑菜单不是谁都能进的**。应用要想把自己的菜单项放进新版右键菜单，得注册成 MSIX 打包应用，然后实现一套新的 `IExplorerCommand` 接口。传统 Win32 软件那套写注册表 `shell` 键的做法，在新菜单里完全无效。

于是现实就变成了：7-Zip 这种老牌工具，功能一个没少，但你在 Win11 上想用它，就得多点一次。

## 我试过的那些「土办法」

在决定自己写之前，我基本把网上能找到的方案都试了一遍。

**方案一：改注册表，把菜单项挂到 `ExtendedSubCommandsKey` 上。**

这是网上流传最广的做法。原理是给某个文件类型注册一个 `ExtendedSubCommandsKey`，指向一组子命令，Explorer 就会把它渲染成带二级菜单的一项。

我照着做了一遍，注册表写进去了，重启资源管理器，右键——菜单项出来了，点开是空的。

查了一圈才明白：`ExtendedSubCommandsKey` 在 Win11 的紧凑菜单里有条件生效，而且它对「动态枚举」的支持很差。7-Zip 的菜单不是静态的十来个固定条目，它是根据你选中的东西实时算出来的——选一个文件是这几项，选十个文件是那几项，选文件夹又是另一套，还带「解压到 "文件夹名\"」这种把目标名字嵌进标题里的条目。静态注册表根本表达不了这个。

**方案二：找现成的第三方工具。**

有那么几个"恢复 Win11 经典右键菜单"的小工具，原理基本都是往注册表里写一个空键，把整个 Win11 新菜单废掉，让系统退回 Win10 那套。

这个方案能用，但代价是把整个新菜单干掉。我其实不讨厌新菜单——它顶部的复制、粘贴、重命名、删除图标挺好用的，速度也快。为了 7-Zip 放弃整个新菜单，属于"为了治脚气把腿锯了"。

**方案三：忍着。**

忍了大概两个月。然后某一天，我在解压第十几个包的时候，看着那个「显示更多选项」，突然觉得不能再这样下去了。

## 那就自己写一个

我的想法很简单：**做一个开关**。

打开它，右键菜单里就有 7-Zip；关掉它，系统回到原样。不要修改系统文件，不要替换 explorer.exe，不要装什么驱动。

更进一步，我还想让两种菜单都能用：

- **旧版菜单**（Win10 那套经典菜单）里，直接出现完整的 7-Zip 菜单；
- **新版菜单**（Win11 紧凑菜单）里，也能有一项「7-Zip」，展开就是原版那一整套。

技术上，这两件事是两条完全不同的路。

### 旧版：做一个壳扩展，把 7-Zip 的菜单「借」过来

旧菜单支持传统的 COM 上下文菜单处理器（`IContextMenu`）。我写了一个 DLL，注册到 `*\shellex\ContextMenuHandlers` 下面。当你在文件上右键时，Explorer 会调用我的 `QueryContextMenu`。

关键在于，我不打算自己实现那 34 条菜单项——7-Zip 有新版本了我还得跟着改，纯属自找麻烦。我的做法是：

1. 在内存里建一个临时弹出菜单；
2. 通过 7-Zip 自己的 CLSID 把它原生的菜单处理器创建出来；
3. 把 Explorer 传给我的那个 `IDataObject` 原封不动地交给它；
4. 让它往我的临时菜单里填内容；
5. 把填好的子菜单整个摘下来，挂到我的菜单项上。

这样出来的菜单，和 7-Zip 原生的**一模一样**——因为它就是 7-Zip 自己生成的。压缩包 34 项、文件夹 21 项、驱动器 21 项，一项不差，「解压到 "xxx\"」里的名字也是对的。

### 新版：MSIX 稀疏包 + `IExplorerCommand`

Win11 的新菜单要求应用是 MSIX 打包的。但完整打包意味着要把整个程序塞进一个安装包，还要走应用商店那套流程，太重了。

有个折中方案叫**稀疏包**（Sparse Package）：只打包一个清单文件，声明「我有一个 COM 扩展在外面」，真正的 DLL 还放在普通目录里。系统认这个身份，你就能进新菜单了。

这部分是整个项目里最折磨人的。清单文件的结构有一堆不成文的规矩：`uap10:AllowExternalContent` 必须放在 `<Properties>` 下面而不是 `<Application>` 下面，`<Extensions>` 必须在 `<Application>` 里面，`TrustLevel="mediumIL"` 和 `RuntimeBehavior="win32App"` 得配对出现，而且不能写 `EntryPoint`。每一条错了，`MakeAppx` 就给你一个 `C00CE015` 或者 `C00CE014`，不告诉你哪儿错了。

然后是签名。稀疏包必须签名，签名必须用受信任的证书，而证书的 `CN` 必须和清单里的 `Publisher` **一字不差**——差一个字母，`signtool` 就给你 `SignerSign() failed 0x8007000B`。还有一个坑：签名的时候如果不加 `/sm` 参数，`signtool` 只会去当前用户的证书存储里找，找不到你在本机存储里装的那张，然后报一个看起来毫无关联的错误。

新版菜单里那棵树的问题更隐蔽。`IExplorerCommand` 的子命令枚举接口（`IEnumExplorerCommand`）在 `EnumSubCommands` 调用时**拿不到你选中的文件**——它只给你一个 `IShellItemArray`，但某些路径下这个参数是空的。我的解法是把选中路径在 `GetTitle` / `GetState` 阶段缓存下来，等 `EnumSubCommands` 被调用时再用缓存重建菜单。

## 关于「提权」这件事

一开始我把新版菜单的安装脚本设计成需要管理员权限，然后立刻就遇到了问题：脚本跑完，退出码 1，日志是空的。

查了很久才发现，原因是 `powershell -File` 在提权的新进程里失败时，脚本根本没跑起来，所以什么日志都没有。改成先写一个 UTF-8 BOM 的 wrapper 脚本，再 `-File` 调用它，并且在 wrapper 里用 try/catch 把启动阶段的异常也写进日志，才终于看到真正的错误。

不过这里有个更根本的限制，我得说清楚：**MSIX 的注册是写在当前用户账户下的**。如果你的账户是标准用户（不在管理员组），那么提权之后注册进去的是**管理员账户**的菜单，你自己登录的账户依然看不到。

这不是 bug，是 Windows 的设计。所以我一直建议：别用「以管理员身份运行」启动这个程序，否则旧版菜单会被写进管理员的 HKCU，你自己反而用不上。

## 顺手加的两个功能

写到这里其实已经能用了。但我自己在装的时候又嫌麻烦，就顺手加了两个东西：

**装 7-Zip**。程序启动时会去找 7-Zip——先查注册表里的安装路径，再查卸载项，再看 `Program Files`，最后扫 `PATH`。找不到的话，主界面上会出现一个「安装 7-Zip」按钮。点进去是一个小向导：选版本（默认最新，从 GitHub 的 release 列表实时拉）、下载（带进度条）、选目录（默认 `C:\Program Files\7-Zip`）、静默安装。

**更新 7-Zip**。已经装了的话，按钮会变成「更新 7-Zip」，自动比对本地版本和 GitHub 上的最新版，落后了就一键升级。版本号比较这里有个小坑：7-Zip 用 `26.06` 这种两位写法，但 GitHub 的 tag 是 `26.06`，而程序内部显示可能是 `26.6`。直接字符串比大小会得出 `26.6 < 26.06` 这种荒谬结论，所以得先把版本号拆成数字再比。

## 现在它长这样

界面是用 WinUI 3 写的，很小，就两页。

**设置页**：显示 7-Zip 的路径（可以手动改）、两个勾选框——「旧版右键菜单」默认开，「新版右键菜单」默认关。底下三个按钮：保存、恢复默认、取消保存。

**关于页**：作者、GitHub、博客、仓库地址。

没有服务，没有后台进程，没有开机自启。关掉窗口就什么都不剩，注册表里只留下你主动勾选的那几项。

## 下载

最新版本是 **v1.3.0**。

- **直接下载**：[7zAIWin11RCM-1.3.0-win-x64.zip](https://github.com/minecraftmc22/7zAIWin11RCM/releases/download/v1.3.0/7zAIWin11RCM-1.3.0-win-x64.zip)（40.1 MB，免安装）
- **发布页**：[github.com/minecraftmc22/7zAIWin11RCM/releases](https://github.com/minecraftmc22/7zAIWin11RCM/releases)
- **源码**：[github.com/minecraftmc22/7zAIWin11RCM](https://github.com/minecraftmc22/7zAIWin11RCM)

解压到任意目录，双击 `SevenZipAIWin11RCM.exe` 就行。

**环境要求**：Windows 11（Win10 1809+ 能运行程序，但新版右键菜单只有 Win11 支持），以及 [.NET 8 桌面运行时](https://dotnet.microsoft.com/zh-cn/download/dotnet/8.0)——如果启动时报缺运行时，装一下这个就好。

**几个使用上的提醒**：

1. 旧版菜单勾选后点保存，立即生效，不需要管理员权限。
2. 新版菜单第一次开启会弹 UAC，而且系统里需要有 Windows SDK 的 `MakeAppx` 和 `signtool`。程序会自动去注册表、`Program Files`、`PATH` 里找；实在找不到，就在设置页展开「打包工具」，把这两个 exe 的路径指过去。
3. 从旧版本升级上来的话，建议先「取消勾选 → 保存」清一次，再重新勾选保存，把早期版本留在注册表里的旧写法清掉。
4. 如果更新程序时提示文件被占用，是因为 `explorer.exe` 还加载着壳扩展的 DLL。先在程序里取消勾选保存，再重启资源管理器，然后覆盖文件。

## 最后

这个项目从想法到能跑，大概花了一个周末，加上后面零零碎碎的修修补补。中间大部分时间不是花在写代码上，而是花在和 Windows 的各种约定较劲——清单文件的层级、证书的 CN、签名的参数、接口的调用顺序。

值不值？我觉得值。现在我右键一个压缩包，7-Zip 就在第一层，点一下，解压。一年能省下一万次点击和一万次等待。

至于项目为什么叫 `7zAIWin11RCM`——`RCM` 是 Right-Click Menu，`AI` 是……嗯，其实没什么特别的含义，就是起名的时候手滑了。

项目用 AGPL-3.0 开源，有想法或者踩到同样的坑，欢迎来仓库提 issue。
